# TokenForge architecture and regression boundaries

The review rounds identified related families of defects, rather than one faulty function. The original one-image utility grew into an editor, a batch processor and a multi-process Explorer integration. Its boundaries must therefore treat mutable external state as a first-class input.

| Boundary | Invariant | Regression strategy |
| --- | --- | --- |
| Image ownership | A filename is not proof of ownership. Inspect the generated marker on the same fingerprint-verified snapshot used for overwrite decisions; V3 records ownership plus independent source and render recipe digests, V2 identifies the recorded source filename, legacy V1 requires an unambiguous stem. Do not automatically overwrite independent art. Explicit overwrite approval is bound to the destination version, checked before either output and again after copy encoding, even if a replacement is marked as owned. Saved previews validate ownership and decode the same snapshot. | Independent/case-sensitive names, collisions, orphaned exports, legacy markers. |
| Source identity | Cache keys and renders describe SHA-256-verified source bytes, not just timestamps. Decode a bounded spooled snapshot on a cache miss. A single export shares a lazy immutable source snapshot between the optional WebP copy and extraction; it rehashes at publication boundaries. The watcher uses metadata first and full verification at least every 30 seconds while idle. GUI and CLI share the extraction policy. | Source replacement, cache corruption, snapshot replacement, cache reuse without model startup. |
| Publication | Encode first, validate, publish atomically where supported, distinguish success with warnings from failure, preserve unexpectedly displaced bytes. Never delete a cache entry after a failed read. | Concurrent writes, replacement failures, recovery paths, late source changes. |
| Async GUI | Tk owns widgets and captures request settings; the worker owns discovery, per-file adjustment construction, saved-preview decoding, frame preparation, export preflight hashing, extraction and composition. The latest-only render queue rejects superseded selection/serial results; token geometry and item orientation are worker-cached. Automatic frame refresh follows the latest selection and does not probe each file in the Tk thread; explicit navigation retains its requested target. During refresh the previously committed list remains visible, but the selected frame and its aliases are not eligible for selection or export. Workers emit a terminal event even on startup errors or a foreign SystemExit. The dispatcher retains the worker reservation through completion handlers, including nested Tk modal loops; overwrite approval pins the source before opening a dialog and suspends dispatch until it returns. Immutable request settings and generation identifiers prevent stale events from selecting another file. Commit a folder selection only on successful discovery, and invalidate discovery when the frame changes. Close waits for cleanup. | Queued export, stale preview, folder discovery, source disappearance, shutdown. |
| Settings | Persist explicit changes and resets against the latest settings under an interprocess lock. GUI lock acquisition is non-blocking with bounded retries. Decode all global options through one schema and require explicit backup recovery for malformed JSON. Corrupt preferences must not silently drive automated export. | Concurrent edits, stale resets, clamped widgets and lock contention. |
| OS integration | New installation creates owned SendTo links only. Snapshot ownership is verified before mutation; detach and inspect the actual displaced file, then publish or restore without clobbering a concurrent replacement. No new writes to shared shell registry branches. Migration removes named legacy TokenForge verbs only. | Real Unicode Windows shortcuts, both third-party install orders, legacy cleanup, unrelated shortcuts. |
| Local inference | The allowed model identifiers are shared and explicitly local; unknown/remote backends cannot be instantiated. | Invalid model on automatic entry, offline cache tests, dependency import checks. |
| Runtime support | Regular 64-bit CPython 3.11–3.13 with working Tcl/Tk, except Windows 3.13.0; a common Pillow constraint; all supported runtimes exercised in Windows CI. Missing or entirely skipped required suites cannot be reported as green. | Offline suite and real dependency installation for each supported interpreter. |

## Limits and deliberate choices

- A non-cooperating external editor cannot be universally locked out. A late source change is reported; the user may regenerate. Existing original WebP copies are never overwritten automatically.
- The logical source path controls naming and output placement; resolved paths identify content and shared placement preferences. Filename collision discovery uses one directory index per batch, followed by targeted native filename queries on Windows and conservative live scans elsewhere. Publication checks relevant names and the exact destination; skip requires a decodable owned image. This cannot stop another application creating a colliding name after publication.
- The GUI keeps the lightweight saved-image viewing path. Full extraction is deferred until necessary; source changes detected during editable preview trigger a refresh. Saved-result-only views keep checking source identity, export metadata and provenance without triggering inference; a missing or corrupt export clears the shown result and the watcher can recover when it reappears.
- SendTo takes one additional menu step and is visible for non-image files; the entry point validates the selection. This removes the shared-registry design risk rather than attempting to predict future machine-wide registrations. Previously created shared registry parents are not removed blindly.
- Tests simulate external-editor races and Windows replacement failures, and launch independent Python processes against real OS locks and atomic create-only publication. Real shortcut creation/readback is exercised in Windows CI, not actual Explorer click interaction or neural inference/model accuracy.

## Release checklist

1. Run the complete Windows test matrix and dependency import checks.
2. Install and upgrade using regular Python on a Windows desktop; check a path containing spaces, Cyrillic and exclamation marks.
3. Exercise actual Explorer SendTo commands, including unsupported/multiple selections, and remove links.
4. Test real inference with the supported local models, including the first model download, and compare visual results on representative art.
5. Test a large folder and network/unavailable source. Keep the UI responsive and avoid claiming that an unmeasured operation is fast.

Manual save captures the logical request, current preview fingerprint (when available), and source/destination metadata at the click. The serialized worker verifies those observations, fingerprints the files, and inspects ownership within the destination snapshot captured during that same single full-file read before asking for consent. The export uses the pinned fingerprints (or explicit expected absence). A no-preview same-metadata external rewrite before preflight hashing cannot be detected in general without synchronous full-file reads or exclusive OS cooperation; metadata operations themselves may still block on unavailable network storage. Linux/macOS replacement uses atomic exchange where available and fails without moving the old name when unsupported; Windows remains the supported desktop platform.

## Resource and release policy (1.8)

- Allowed source formats are PNG/JPEG/WebP/BMP/TIFF. Encoded size and pixel/side limits are checked before full decoding; WebP canvas dimensions are preflighted on the same stream before Pillow creates a native decoder, including the 4096 square ring limit. Legacy WebP markers can still be discovered without opening a decoder. Color-tagged sources are normalized to sRGB before composition.
- Cutout memory LRU is bounded by 6 entries and 256 MiB decoded RGBA, excluding displayed/working images and native inference allocations. The disk cache reconciles actual encoded bytes and entry count under a shared maintenance lock before each publication (2 GiB / 4096 entries by default). A busy lock or failed eviction skips the optional write rather than expanding the cache. Hits never scan the directory. Only digest-named regular PNG files participate. One model session is retained per process and a cross-process lock serializes uncached inference in the shared preferences directory. Verified transparent sources can bypass a busy or inaccessible inference lock without writing an unlocked disk cache entry; neural inference always reserves the lock and repeats the cache lookup. Contended opaque alpha probes release their pixel buffer before waiting.
- Cache revisions include relevant library versions and metadata of the exact selected rembg 2.0.87 weight file (per-model first, legacy second), not cryptographic hashes of large model weights. Both disk keys and export recipes share the normalization revision. Existing model sessions are replaced when the observed revision changes. Output recipe digests use the exact revision returned by the shared extraction service (including after first download). Saved-only and editable previews also observe changes in model revision. This is conservative for transparent-source bypass: a model upgrade may prompt a freshness warning even if the bypass pixels would not change.
- Token recipe digests include both frame and interior-mask bytes, dimensions and modes. Earlier token recipe digests may warn that settings changed; cache keys and existing images are not invalidated or overwritten by this change. Current parameters are read after validating a skipped export, and new writes use their actual extraction revision.
- All five skip paths use a common protocol: capture a fingerprinted destination snapshot and validate pixels/owner; evaluate current recipe and live collisions/approval; hash destination and source again and compare metadata across the final checks. This is a point-in-time observation, not a transaction with unrelated external editors. No slow recipe lookup follows the final file checks.
- Operation-specific budgets in `resource_policy.py`: 64 Mi pixels decode / 16384 side, 4096 square ring, 1024 output side, 16 Mi pixels token-scale temporary buffer; uncached ordinary inference 16 Mi pixels, decontamination 4 Mi pixels, and alpha matting 1 Mi pixel. Oversized extraction is rejected before model creation; transparent bypass and valid cache hits do not perform the costly operation. These limits constrain workload, not whole-process RSS or native model allocation. Quality and source resolution are not silently changed.
- `image_normalization.py` separates container sample layout, EXIF orientation, alpha, and ICC conversion. Supported integer grayscale sample depths are normalized using the declared unsigned sample range (12/16-bit TIFF and 16-bit PNG included); palette, RGB, CMYK, LA/RGBA and premultiplied alpha are handled explicitly. Signed, float and 32-bit integer intensity data need a user-selected display range and are rejected rather than silently clamped. The versioned decoder changes require one-time cutout regeneration on demand; saved pixels remain untouched.
- Freshness is independent of ownership. Old markers are not silently promoted, stale copies are not automatically overwritten, and warnings preserve the user's skip choice.
- Windows constraints record tested package versions per Python minor version. They do not pin wheel hashes. CI runs on main pushes as well as PRs; an advisory workflow scans the pinned versions. The Windows GUI smoke runs real Tk widgets/event processing on synthetic transparent art. The installed-backend smoke exercises real rembg/PyMatting cleanup on synthetic masks without downloading weights. Neither exercises actual Explorer clicks, actual ONNX inference accuracy, or peak memory on a user's hardware.
