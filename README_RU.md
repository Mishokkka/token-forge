# TokenForge v1.8.0 — токены персонажей и изображения предметов

Программа для Windows 10/11. Создаёт WebP-изображения с прозрачным фоном локально, без облачной отправки артов. Для удаления фона использует rembg и модели BiRefNet; кэш вырезок работает для обоих режимов.

## Исправлено в v1.7.1: предметы никогда не обрезаются

- При всех трёх вариантах расположения предмет **целиком помещается в квадрат**, включая чёрную обводку 3 px.
- Масштаб 100% соответствует **максимальному размеру, помещающемуся без обрезки** при текущем повороте. При попытке выставить масштаб выше 100% он автоматически ограничивается максимумом, чтобы не обрезать предмет.
- Горизонтальный и вертикальный сдвиги изменяют центр предмета. При необходимости программа уменьшает масштаб, чтобы предмет не обрезался.
- В режиме «По центру» сохраняется отступ минимум ~5% от краёв, при диагоналях ~1.8%. Отступы учитывают толщину обводки.
- По умолчанию «Игнорировать почти прозрачный мусор» удаляет пиксели с альфой меньше 8/255. Отключи настройку для сохранения намеренно слабых полупрозрачных деталей.
- Для обновления используй полный ZIP исходников из раздела ниже, а не отдельные файлы: модули программы должны быть одной версии.

## Новое в v1.7: режим «Предметы»

В верхнем правом углу окна переключи **«Токены» / «Предметы»**.

Предметы сохраняются в **500 × 500, WebP без потерь, прозрачный фон, чёрная обводка 3 px**. Поддерживаются три композиции:

- **По центру**: без автоматического поворота, вся вырезка вписывается в квадрат с отступом примерно 5% со всех сторон.
- **Диагональ ↗**: продольная ось предмета выравнивается снизу-слева вверх-вправо. Предмет масштабируется почти до углов квадрата с небольшим защитным отступом.
- **Диагональ ↘**: аналогично, сверху-слева вниз-вправо.

В режиме предметов доступны индивидуальные регулировки масштаба, смещения и добавочного поворота. Изменения запоминаются для каждого изображения в `%LOCALAPPDATA%\TokenForge\settings.json` независимо от настроек токенов персонажей. Выбор диагонали помогает вытянутым предметам, например оружию. Для округлых предметов лучше подходит центр.

Название результата: `Меч.png` → **`Меч_item.webp`**. Если включена опция конвертации, рядом также будет `Меч.webp`, обычная WebP-копия оригинала. Исходный PNG не изменяется.

Токены персонажей по-прежнему сохраняются как `Мечt.webp` или `Мечt.png` в зависимости от выбранного формата. Предметы и токены не перезаписывают друг друга. В обоих режимах готовые изображения можно открывать без повторного запуска нейросети. Извлечённые вырезки хранятся в `%LOCALAPPDATA%\TokenForge\cutouts`.

## Скачать и обновить

- [ZIP основной ветки](https://github.com/Mishokkka/token-forge/archive/refs/heads/main.zip).
- История изменений: [CHANGELOG](CHANGELOG.md).

Отдельные старые архивы v1.7.1 в репозитории не опубликованы. Один и тот же ZIP подходит для новой установки и обновления.

1. Закрой TokenForge.
2. Распакуй ZIP и скопируй содержимое его внутренней папки в существующую папку TokenForge с заменой файлов. Обновляй комплект целиком: `tokenforge.py`, `token_engine.py`, `item_engine.py`, `token_cli.py`, `runtime_streams.py`, `app_paths.py`, `settings_store.py`, `process_lock.py`, `local_models.py`, `cutout_service.py`, `resource_policy.py`, `image_normalization.py`, `context_menu.py`, `sendto_entry.py`, `python_compat.py`, `diagnostics_tests.py`, BAT-скрипты, оба файла `requirements*.txt`, папку `constraints`, вспомогательные модули, рамки и тесты. Сохрани свою нестандартную рамку отдельно, если она имеет имя одного из штатных файлов. Существующую `.venv` и папку кэша не удаляй.
3. Сначала выполни `install.bat`: минимальные версии Pillow и rembg повышены из соображений безопасности. Затем запусти `run.bat`.
4. Если контекстное меню было установлено прежней версией, повторно запусти `install_context_menu.bat` для миграции команд. Это относится и к v1.7.

Настройки сохраняются. В версии 1.8 изменён формат ключей кэша: потребуется однократное создание вырезки с новым ключом, если она понадобится для редактирования или нового результата.

## Полная установка на Windows

1. Скачай ZIP по ссылке выше и распакуй содержимое его внутренней папки, например в `C:\TokenForge`.
2. Установи обычный CPython **3.12 64-bit** (не free-threaded), если он ещё не установлен. Установка Python должна включать Tcl/Tk. Версия 3.13.0 для Windows не поддерживается из-за ошибки Tk в виртуальных окружениях: сначала обновись до 3.13.1 или новее. С Python Install Manager можно выполнить в CMD `pymanager install 3.12`; проверка: `py -3.12 --version`.
3. Установи [Microsoft Visual C++ Redistributable x64](https://aka.ms/vs/17/release/vc_redist.x64.exe), необходимый ONNX Runtime. Если импорт ONNX Runtime не проходит, установи этот компонент и повторно запусти установщик. Запусти `install.bat`. Он создаст `.venv` и установит Pillow, rembg, ONNX Runtime и tkinterdnd2.
4. Запусти `run.bat`. При первом удалении фона нужная модель будет скачана один раз, затем будет использоваться локально.
5. По желанию запусти `install_context_menu.bat` для добавления команд в ПКМ по изображению. Он работает для текущего пользователя Windows и не требует администратора. Новая интеграция использует штатную папку ярлыков Windows SendTo и Unicode API Windows Shell Link, не создавая общих ключей реестра. Для установки ярлыков требуется штатный Windows PowerShell 5.1.

**Важно:** если перенёс программу, запусти её из новой папки, повторно выбери перемещённую рамку и сохрани настройки перед автоматической обработкой. Затем повторно выполни `install_context_menu.bat`. Для удаления пунктов меню есть `remove_context_menu.bat`.

## Контекстное меню Windows

ПКМ → «Отправить» → TokenForge. В Windows 11 сначала может потребоваться «Показать дополнительные параметры». Все четыре действия доступны в подменю «Отправить» для любого файла, но программа принимает только одно поддерживаемое изображение (PNG/JPG/JPEG/WebP/BMP/TIF/TIFF):

- **Сделать автоматический токен**: прежний генератор персонажей с сохранёнными настройками.
- **Открыть в TokenForge**: открыть выделенный арт во вкладке токенов.
- **Сделать арт предмета**: автоматически создать `Имя_item.webp` без основного окна, по настройкам предметов.
- **Открыть предмет в TokenForge**: открыть этот арт сразу в редакторе предметов.

Автоматические команды используют текущую модель фона, постоянный кэш, настройки конкретного арта, опции конвертации оригинала и пропуска готового файла. Если подтверждённый результат уже есть и галочка **«Пропускать готовые изображения»** включена, программа пропустит его. Кнопка **«Сохранить выбранный»** в основном окне перезаписывает выбранный результат намеренно. Новые токены, предметы и WebP-копии оригиналов помечаются в метаданных. Старые непомеченные файлы считаются самостоятельными изображениями: название не доказывает происхождение. Чтобы заменить старый токен или предмет, выбери именно исходник и явно подтверди перезапись в интерфейсе. Старую непомеченную WebP-копию перемести в другую папку или переименуй, если её наличие мешает экспорту. Независимые исходники с одинаковым базовым именем необходимо переименовать. При конфликте с внешним редактором в момент замены программа сохраняет вытесненную версию файла в соседней папке `.tokenforge-recovery` и сообщает её путь. Если исходник изменился непосредственно при публикации, уже записанный результат отмечается предупреждением: для токена или предмета повтори обработку с отключённым пропуском готовых изображений; для WebP-копии перемести или удали устаревшую копию и повтори обработку. Повреждённую WebP-копию также нужно переместить или удалить вручную.

**Миграция:** повторно запусти `install_context_menu.bat`. Сначала устанавливаются четыре ярлыка в SendTo, затем удаляются только старые именованные команды TokenForge. Общие родительские ключи реестра намеренно не удаляются: прежняя версия могла оставить пустой ключ, а его происхождение нельзя установить безопасно. `remove_context_menu.bat` удаляет собственные ярлыки и старые именованные команды. Если Python недоступен, открой `shell:sendto` через Win+R и проверь поле «Комментарий» в свойствах каждого ярлыка и удали только ярлыки TokenForge с точным значением `TokenForge.SendTo.v1`; старые записи реестра требуют отдельной миграции. При конфликте с внешней заменой ярлыка программа сообщает о восстановлении либо о пути сохранённой копии. При необходимости проверить ранее оставшиеся общие ключи следует вручную после резервного копирования реестра.

Если обработка через ПКМ завершилась с ошибкой, проверь `%LOCALAPPDATA%\TokenForge\context_actions.log`.

## Командная строка

Можно запустить и вручную из папки TokenForge:

```bat
run.bat --open "C:\Arts\Hero.png"
run.bat --auto "C:\Arts\Hero.png"
run.bat --open-item "C:\Arts\Sword.png"
run.bat --auto-item "C:\Arts\Sword.png"
```

`--open` / `--open-item`: открыть интерфейс на выбранном файле. Только метаданные подтверждённого токена, предмета или WebP-копии перенаправляют на однозначно найденный исходный арт; команды Проводника используют тот же алгоритм. Непомеченные файлы открываются самостоятельно.
`--auto` / `--auto-item`: обработать один файл с сохранёнными настройками. Основное окно не открывается, появляется короткое уведомление.

## Пакетная обработка

Выбери папку, переключи режим и нажми **«Обработать всю папку»**. Каждый исходник будет обработан независимо, ошибки одного изображения не прерывают остальные. Сохранение идёт рядом с исходными файлами. Помеченные результаты и WebP-копии не попадают в новую обработку, даже если исходник перемещён. Для старых непомеченных файлов автоматическое исключение по имени намеренно отключено. Чтобы перегенерировать отдельный результат, нажми **«Сохранить выбранный»**.

Необязательно удалять фон вручную: уже прозрачные PNG/WebP можно обрабатывать без нейросети при включённой опции сохранения альфа-канала.

## Диагностика и ограничения

- Проверка установки: `check_install.bat`. Диагностика проверяет совместимость Python и Tcl/Tk, наличие обязательных наборов тестов и их фактическое выполнение. Полностью пропущенный обязательный набор не считается успешной проверкой.
- Автотесты: `.venv\Scripts\python.exe -m unittest discover -v`.
- Обычные офлайн-тесты проверяют движок, настройки, CLI и имитацию Windows API. Windows CI проверяет работоспособность настоящих ярлыков в изолированной папке, откат и миграцию на моделируемом реестре, а также ставит зависимости и запускает офлайн-тесты на Python 3.11–3.13. Отображение в Проводнике и нейросетевая вырезка проверяются вручную.
- Автоматическое определение продольной оси рассчитано на вытянутые предметы. Для предметов неправильной формы можно выбрать «По центру» или поправить поворот вручную.
- Режимы удаления фона не изменились по сравнению с v1.6. На сложных исходниках качество зависит от выбранной модели.

## Важные изменения в 1.8

- Предпросмотр и подготовка рамок работают в фоне. Серия быстрых перемещений ползунка объединяется в последний запрос. Во время пакетного экспорта новый предпросмотр может ждать освобождения рабочего потока.
- Новый результат содержит метаданные TokenForge/3: имя, тип, SHA-256 исходника и хэш параметров генерации. Старые помеченные файлы поддерживаются, но их актуальность может быть не подтверждена. При включённом пропуске устаревший результат не перезаписывается и сопровождается предупреждением. Для повторной генерации токена/предмета используй «Сохранить выбранный» или отключи пропуск; устаревшую WebP-копию перемести или удали отдельно.
- Старые непомеченные изображения намеренно не принимаются за токены по суффиксу: для безопасного обновления открой исходник, выбери нужный режим и явно подтверди замену старого результата.
- Допустимые декодеры: PNG, JPEG, WebP, BMP, TIFF; лимиты исходника 256 МиБ, 64 МиПикс, сторона 16384 px; рамки до 4096 × 4096. Цветовые профили преобразуются в sRGB. Повреждённый профиль требует предварительного сохранения арта в sRGB. Для нового удаления фона действуют отдельные лимиты: «Обычный» 16 МиПикс, «Очистка краёв» 4 МиПикс, Alpha Matting 1 МиПикс. Для более крупного арта уменьши разрешение или выбери менее ресурсоёмкий режим; уже прозрачный арт и актуальный кэш не требуют нейросети. Знаковые, вещественные и 32-битные целочисленные изображения требуют предварительной нормализации диапазона в 8/16-битный формат.
- Кэш RGBA в памяти ограничен 256 МиБ и шестью записями, отдельно от текущего предпросмотра и временных рабочих буферов. Сохраняется одна модель на процесс; одновременно выполняется одна операция нейросетевой обработки между экземплярами с общим каталогом настроек. Дисковый кэш ограничивается 2 ГиБ / 4096 записями при каждой новой публикации под общей блокировкой. Если освободить место не удалось, новая запись кэша пропускается. Чтение готового кэша не сканирует каталог.
- При некорректном JSON интерфейс предлагает явное восстановление с резервной копией. Автоматическая команда не использует некорректные настройки для записи.
- Установка использует отдельные ограничения версий пакетов для Python 3.11, 3.12 и 3.13. Это фиксация версий пакетов, не хэшей бинарных колёс.
- Дополнительная проверка настоящего интерфейса: `.venv\Scripts\python.exe gui_smoke.py`. Она не меняет пользовательские настройки, не загружает модель и не проверяет фактическое меню Проводника.

### Готовность модели и отмена
В редакторе отображаются наличие локального файла модели, скачанные МБ, проценты/скорость/оставшееся время при известном размере, отдельные этапы инициализации ONNX и удаления фона. Для нейросетевой обработки показывается прошедшее время без выдуманных процентов. «Остановить» или закрытие окна отменяет загрузку/нейросетевую обработку; уже сохранённые результаты остаются на месте. Наличие файла не гарантирует успешную инициализацию. Журнал этапов и ошибок: `%LOCALAPPDATA%\TokenForge\inference.log`. Автоматические действия через Explorer остаются без окна редактора.
